# Lixx desktop audit

**21 November 2026 · Ubuntu 26.04 amd64**

The current working tree installs a usable Hyprland desktop from a TTY. The workstation matches the files Lixx manages. The first fixes I would make are the lock lifecycle, the Ghostty working-directory shortcut, and the missing default editor. A fresh clone still delivers an earlier desktop.

After the audit, Lixx added the workstation's Neovim configuration and PDF toolchain. A fresh guest opened all 62 locked plugins and exported Markdown to PDF and HTML. Automatic locking and screen blanking are always enabled in Lixx. Manual and logind locking worked, and the password prompt survived a Hypridle restart. The workstation and VM ran Waybar and SwayNC with clean service logs. The Epiphany realtime-portal warning reproduced and is documented with the upstream fix. ## Fix first

1. **The former idle toggle also disabled lock handling.** It stopped Hypridle, which handled logind lock requests, the notification-center lock button and pre-suspend locking. The old wrapper also required wallpaper setup and a keyboard-layout switch to succeed before it started Hyprlock, then discarded the locker's exit status. The ordinary password path passed in a VM. The failure-path finding came from code review. [Hypridle configuration](targets/all/trees/home/.config/hypr/hypridle.conf#L1) · [Lock wrapper](targets/all/trees/home/.local/share/lixx-system/bin/lixx-lock#L4) · [Notification button](targets/all/trees/home/.config/swaync/config.json#L71) · [Hypridle event handling](https://wiki.hypr.land/hypr-ecosystem/user/hypridle/)
2. **Super+Ctrl+Return loses the focused shell's working directory.** I opened two Ghostty windows with different, verified shell directories. Both windows shared one Ghostty PID. Focusing each in turn made the helper return the home directory for both. Launching the installed helper opened the third shell in home. There are two issues to fix together. Walking a process tree does not identify a focused surface, and the helper passes `--dir` where Ghostty documents `--working-directory`. Keep the two-window case as the acceptance test. [Lixx terminal launcher](targets/all/trees/home/.local/share/lixx-system/bin/lixx-terminal#L9) · [Ghostty's new-window implementation](https://github.com/ghostty-org/ghostty/blob/v1.3.0/src/cli/new_window.zig)
3. **The clean desktop configures an editor it never installs.** Both `EDITOR` and `VISUAL` resolve to `nvim`. The workstation has it via Snap. The clean Server guest had no `nvim` executable. Add Ubuntu's `neovim` package to honor the current default. Whether to ship the workstation's personal Neovim setup is a separate choice. [Session defaults](targets/all/trees/home/.config/env/session.sh#L3) · [Package list](targets/ubuntu-26.04/packages.txt#L47)
4. **The tested desktop is unpublished.** The remote `main` still points to `4bef276`. At audit start, 36 untracked files under `targets/` and `LICENSES/` included all nine Lixx programs, the archive manifest and both launcher services. The VM includes untracked files, which explains why the preview can pass while a fresh clone installs the earlier version. Review the intended files and executable bits, commit them, then repeat the VM test from that exact commit before publishing. ## Installer, upgrades and maintenance

- **Update coupled files together.** Elephant and its eight Go providers are pinned to one release, but the installer offers independent yes/skip decisions and writes each file separately. Skipping one changed provider or interrupting a future upgrade can leave a mixed installation. A systemd daemon reload picks up changed unit definitions. Replacing an executable alone leaves the previous process running until restart. Present a single accept/skip choice for the coupled provider set and make the required restart or next-login boundary visible. The workstation's current user manager still advertised `TERMINAL=xdg-terminal-exec`, while a fresh session advertised `ghostty`. [Installer review and apply](lixx#L532) · [Elephant releases](targets/ubuntu-26.04/archives.toml#L10) · [Go plugin compatibility](https://pkg.go.dev/plugin)
- **Define what the single install command updates.** It refreshes APT and satisfies 71 package requirements. A read-only simulation against the workstation's current indexes selected zero installs or upgrades and listed 65 packages outside the transaction. Ordinary Ubuntu upgrades still use Ubuntu's update mechanism. Every Lixx run also downloads the pinned UWSM package into a temporary directory and rebuilds roughly 257 MiB of staging, even with matching installed files and 18 cached archives. An unrelated unavailable APT source can block a config-only change. Keep the one command and document or streamline the no-change path. [APT transaction](lixx#L480) · [Archive staging](lixx#L144) · [APT command semantics](https://manpages.debian.org/unstable/apt/apt-get.8.en.html)
- **Account for previous installations.** Hash-based retirement correctly removed five unmodified files in the upgrade test. Fuzzel from the previous release remained installed. Older battery-helper, font and UWSM override paths are described in the README and absent from the retirement list. The reference workstation's original Omarchy cleanup was a separate migration. Another customized account still needs that inventory and review. No active Omarchy commands or checkout links surfaced in the inspected desktop paths here. A 1.1 GB rollback archive and an older Elephant backup with Omarchy-named menu files are still present. Keep cleanup reviewable and preserve personal files. [Retirement list](targets/all/retired.sha256) · [Documented historical paths](README.md#file-review-during-installation)
- **Make the graphical check repeatable.** The preview's exit check accepts a successful installer marker even if no usable desktop was observed. The repository has three preview tests and four desktop helper tests. The interactive preview and the temporary VM probes used for this audit answer different questions. A small repeatable check for a UWSM session, a monitor, zero Hyprland config errors, visible Waybar, and a working launcher would catch the gap. Keep the interactive preview for visual testing. [Preview exit check](vm/run#L134) · [Preview tests](tests/test_vm.py#L70) · [Desktop tests](tests/test_desktop.py)
- **Tighten two configuration edge cases.** A relative `ZDOTDIR` maps Zsh files relative to the installer's current working directory. An isolated staging check placed `.zshrc` in the caller's directory outside the mock home. Reject relative values or define a consistent base. Separately, APT source reuse compares index URLs and does not compare the configured signing key. The workstation and shipped keys matched when independently inspected. Validate the signing identity before reusing somebody else's entry. [Home destinations](lixx#L204) · [APT source reuse](lixx#L414)
- **Prepare for the first locally compiled Lixx program.** Today's nine first-party commands are scripts. The battery listener uses UPower change notifications. The installer copies regular files and stages pinned upstream archives. The Ubuntu and PPA packages resolve against the indexes available at install time. When the first locally compiled helper arrives, feed its build output into the existing review and copy process. For a distributable release, also record the default wallpaper's origin and choose a project-level license. The repository already includes notices for the Walker layout, SwayNC stylesheet and fonts. [Staging](lixx#L134) · [Third-party notices](LICENSES) · [Font license](targets/all/trees/home/.local/share/fonts/JetBrainsMonoNerd/OFL.txt)

The workstation's paired Bose QC headphones reconnected when WirePlumber registered its Bluetooth endpoints. PipeWire selected the headphones as the default stereo output and BlueZ reported an active A2DP transport.

Real fingerprint unlock, physical suspend and resume, lid events, a battery crossing 15/10/5 percent, docked output changes and physical microphone/camera quality still need a hardware pass.
